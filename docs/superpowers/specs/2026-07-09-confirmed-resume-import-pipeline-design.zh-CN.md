# 经确认的简历导入流程设计

**状态：** 已于 2026-07-09 确认

## 目标

简历导入必须在用户明确确认后才开始。检查、转换、时间线合并和结构化抽取等完整文档处理流程全部由 BioTwin API 负责。客户端只提交已确认文件、轮询并显示 API 状态、发送用户命令以及应用最终结果。第三方转换服务始终是 API 的内部实现细节。Markdown 文档跳过转换。用户可以取消正在执行的导入，并在同一个进度对话框中看到可操作的错误说明。

## 范围

该行为应用于两个导入入口：

- 创建简历向导等待用户点击 **Continue**。
- 高级 Workspace 等待用户执行明确的 **Import** 命令。

选择文件时可以在本地读取和校验文件，但不得调用 API、上传内容、转换内容、合并简历或调用信息抽取。

## 待确认文件

客户端使用 `PendingResumeUpload` 模型保存每个已选择文件的名称、MIME 类型、大小和字节内容。这样替换、取消和重试都不依赖可能失效的浏览器文件句柄。

创建简历向导显示一个待确认文件并提供 Replace。Workspace 显示待确认文件列表，用户可以在导入前删除文件。现有文件大小和空文件校验在本地执行。

## 单用户操作协调器

同一个用户在连接当前 API 进程的所有客户端之间只能拥有一个活动的简历创建或导入会话。创建简历向导第一次点击 Continue，以及 Workspace 执行 Import 时，都必须在开始任何处理或编辑前取得操作租约。

`IResumeOperationCoordinator` 定义取得、校验、续订和释放操作。当前 `MemoryResumeOperationCoordinator` 使用单例内存按用户保存一份租约。每份租约包含不透明的操作 ID 和过期时间。客户端编辑期间通过心跳续租，API 后台导入任务自行续租。保存和明确取消会释放租约；被遗弃的客户端会在配置的超时时间后失去租约。

另一个客户端尝试取得租约时，API 立即返回 `409 Conflict`，错误代码为 `resume_operation_in_progress`，用户消息说明已有简历正在创建或导入。第二个客户端不会上传或处理任何文件。

该抽象有意保持与未来 Redis 实现兼容。当前内存实现不能协调多个 API 实例，API 重启时也会丢失租约。重启后客户端必须重新取得租约才能继续或保存；状态令牌校验仍会防止旧数据覆盖较新的简历。

## 简历状态新鲜度

API 根据用户当前的 `ResumeEntries` 计算不透明的简历状态令牌。计算时按语言和 ID 排序，并包含每条记录的 ID、语言、`UpdatedAt` 和源文件哈希。简历列表和详情响应返回当前令牌。客户端在取得操作租约以及保存结果时，都必须提交最近一次收到的令牌。

API 在开始导入前比较一次期望令牌，并在写入简历数据的事务中重新计算和比较。令牌不一致时返回 `409 Conflict`，错误代码为 `resume_state_stale`；客户端刷新简历状态后才能重试。保存、替换或删除成功后，更新后的数据库状态会自然产生新的令牌。

现有 `(TenantId, Language)` 唯一索引继续作为每种语言只能有一份正式简历的最终数据库保护。保存操作不再允许旧客户端静默替换同语言简历。

## 导入阶段

阻塞式对话框使用已确认的紧凑横向阶段轨道。界面只显示简短阶段名称、当前阶段的一句说明和 API 返回的总百分比。

创建简历向导阶段：

1. 上传：0-15%
2. 检查：15-25%
3. 准备：25-65%
4. 合并：65-82%
5. 结构化：82-100%

Workspace 阶段：

1. 上传：0-20%
2. 检查：20-30%
3. 准备：30-80%
4. 草稿：80-100%

不需要执行的阶段显示为 `Skipped`，总百分比直接前进到下一个边界。例如 Markdown 文件跳过“准备”，不存在同语言简历时跳过“合并”。

## API 导入流程

客户端使用 `wizard` 或 `workspace` 模式启动 BioTwin 导入任务。API 保存完整任务状态，并在后台执行所有文档处理阶段。

对于向导任务，API 依次检查文件、准备 Markdown、在需要时查找并合并现有同语言简历，最后抽取可编辑的简历结构。对于 Workspace 任务，API 检查并准备所有已确认文件，然后返回可编辑草稿结果。客户端在导入流程中不再调用合并或抽取接口。

BioTwin API 使用 `.md` 或 `.markdown` 扩展名以及 `text/markdown` MIME 类型识别 Markdown。Markdown 字节使用严格 UTF-8 解码，并直接进入后续 API 阶段。编码无效时返回用户可处理的文件错误。

其他支持的文件类型由 API 发送给配置的转换服务。转换服务的 URL、任务 ID、名称、消息和错误都不能出现在客户端契约或 UI 文案中。

公开契约改为由 BioTwin 定义的 `ResumeImportJobDto`。它包含总进度、当前阶段、所有可显示阶段的状态、取消状态、错误代码、恢复建议，以及最终的向导或 Workspace 结果。第三方进度映射到“准备”阶段，而不是原样暴露。

## 取消

进度对话框始终提供 **Cancel import**。

- 客户端通过每次导入独立的 `CancellationTokenSource` 取消当前上传或轮询请求，并向 API 发送取消命令。
- 已取得 BioTwin 任务 ID 时，客户端调用 `DELETE /api/resumes/import-jobs/{jobId}`。
- API 为完整任务持有取消源。它校验租户所有权，取消合并和抽取调用，将任务标记为已取消，忽略之后的第三方结果，并在后续查询中返回取消状态。
- 明确取消会释放简历操作租约，界面回到待确认文件状态，并保留已选文件，以便重试或替换。Retry 和 Choose another file 保留并续订当前租约。

当前转换服务没有可靠的物理取消接口。已经启动的第三方转换线程可能继续在后台结束，但 BioTwin 不会继续轮询、接收或处理其结果。API 边界为将来接入物理取消能力保留扩展点。

## 错误体验

错误保留在阻塞式对话框内。横向轨道标记失败阶段，并显示：

- 简短的用户可理解原因；
- 一条具体处理建议；
- 可恢复错误提供 **Retry**；
- 无效或不支持的文件提供 **Choose another file**；
- 所有错误都提供 **Cancel import**。

界面不显示异常堆栈、第三方服务名称、内部地址或第三方原始消息。取消是中性结果，不作为错误显示。

## 客户端职责

客户端不计算文档处理进度，也不编排转换、合并或抽取。客户端只负责待确认文件选择、明确确认、取得并续订操作租约、上传已确认文件、轮询 `ResumeImportJobDto`、显示 API 返回的阶段和百分比、发送取消或重试命令，以及把完成结果应用到界面。创建简历向导只有在 API 任务达到 100% 后才进入下一步。Workspace 显示由 API 管理的批次和当前文件状态。

遇到 `resume_operation_in_progress` 时，对话框说明另一个客户端已经占用简历会话。遇到 `resume_state_stale` 时，对话框要求用户刷新后重试，并且不会启动导入。

## 测试

必须覆盖：

- 选择文件不会发起 API 请求；
- Continue 和 Import 分别启动对应流程；
- 同一用户并发取得操作租约时返回 `409 Conflict`；
- 过期的内存租约可以被安全取得，活动租约不能被抢占；
- 租约心跳、保存、取消和超时会正确更新租约状态；
- 过期的期望简历状态令牌会在上传、合并或保存前被拒绝；
- 简历修改成功后会产生不同的状态令牌；
- Markdown 跳过外部 HTTP 处理器；
- 向导导入中的合并和结构化抽取由 API 而不是客户端调用；
- 第三方消息和名称不会进入客户端 DTO；
- API 任务进度映射到正确的总体阶段和百分比；
- 被跳过的阶段正确显示；
- 取消会停止客户端工作并将所属 API 任务标记为已取消；
- 一个租户不能取消另一个租户的任务；
- Retry 和 Choose another file 保留预期状态；
- 错误及恢复建议显示在对话框内；
- 客户端导入路径不再包含合并或抽取编排调用；
- 现有导入、合并、抽取、保存和导航测试继续通过。

## 不在范围内

- 持久化未完成的导入草稿。
- 物理终止当前第三方转换线程。
- 并行执行 Workspace 导入。
- 向浏览器暴露第三方专用诊断信息。

## 数据库影响

本功能不修改数据库结构，也不需要 SQL 迁移。现有 `ResumeEntries` 的更新时间、源文件哈希以及 `(TenantId, Language)` 唯一索引提供持久化状态输入和最终唯一性保护。API 启动时的数据库结构验证行为保持不变。

# BioTwin AI 全站统一布局设计

## 背景

BioTwin AI 当前同时存在居中页面、接近全屏的工作区、独立悬浮导航和多套面板样式。各页面分别控制宽度、间距和顶部偏移，导致页面之间缺少共同的视觉基线，也使简历工作区与公共候选人页面看起来像不同产品。

本次重构以 `C:\Tools\stitch_modern_glassmorphism_portfolio` 中的 Obsidian Glass 设计为视觉参考，放弃当前悬浮胶囊 Header 和分散的页面宽度规则，建立统一的站点框架。

## 目标

- 建立全站共享的 Header、内容轴、页面留白和响应式规则。
- 让普通页面严格对齐到同一条 `1200px` 内容轴。
- 允许简历工作区在一致的站点框架内扩展到约 `1600px`。
- 使用分步向导引导用户从空白或已有文件创建简历，避免把导入、填写、预览和高级编辑堆在一个页面。
- 统一面板、表单、按钮、菜单和对话框的 Obsidian Glass 视觉语言。
- 保留现有路由、权限、数据接口和业务流程。
- 在桌面、平板和手机上避免重叠、溢出及不可用的编辑区域。

## 非目标

- 不改变正式简历保存、每语言唯一、section 拆分、向量生成、候选人展示数据和 profile hash 更新的既有语义；只允许增加不写数据库的向导预填契约。
- 不重新设计页面的信息架构或添加新的业务功能。
- 不要求所有页面使用完全相同的内部栅格。
- 不引入新的前端框架；继续使用现有 Blazor 与样式构建方式。
- 第一版不持久化未完成的向导草稿，也不支持跨会话恢复进度。

## 已选方案

采用“共享页面外壳 + 宽工作区修饰符”。普通页面共享 `1200px` 内容容器；简历工作区使用约 `1600px` 的宽容器。两类页面共享 Header、背景、水平安全边距、顶部起点、设计令牌和响应式断点。

该方案在视觉一致性与编辑器可用空间之间取得平衡。固定所有页面为 `1200px` 会压缩三栏编辑器；继续允许页面自行决定宽度则会保留当前问题。

## 全局站点框架

`MainLayout` 负责渲染唯一的站点外壳：主题背景、固定 Header、内容容器和全局对话框。页面不再自行设置全局水平边距或相对视口的宽度。

站点外壳提供两种明确的内容宽度：

- `site-container`：最大宽度 `1200px`，用于 Home、Projects、Skills、Chat、Settings、Resume Library、Upload、Edit 和 Export 等普通页面。
- `site-container-wide`：最大宽度约 `1600px`，用于 Resume Workspace 等需要三栏工具界面的页面。

两种容器使用相同的响应式侧边距。桌面侧边距约为 `32px`，窄屏逐步缩小到 `16px`。内容从固定 Header 下方的统一位置开始。

## Header

当前独立悬浮的品牌块、胶囊菜单和吊灯式主题按钮将被移除。新 Header 参考 Obsidian Glass：

- 固定在视口顶部，横向占满整个页面。
- 使用半透明背景、背景模糊、细底边和克制的阴影。
- Header 内部最大宽度为 `1200px`，与普通页面内容轴对齐。
- 品牌位于左侧，Home、Projects、Skills 位于中间，主题与账户操作位于右侧。
- 当前导航项使用细线高亮指示器，并在切换时保留平滑过渡。
- 未登录时显示登录入口；登录后显示一个合并的 Admin 入口。
- Admin 下拉菜单包含所有受保护功能，并在选择项目、点击菜单外部或导航完成后关闭。

移动端 Header 仅保留品牌、主题按钮和菜单按钮。公共导航、登录入口和 Admin 功能合并到一个下拉面板中，防止顶部控件重叠。

## 页面布局

普通页面使用统一的页面标题区、区块间距和内容栅格。页面标题、说明、操作区和第一块内容沿同一垂直节奏排列，不再由每个页面重复定义顶部偏移。

Home 的候选人信息、时间线和内容卡片继续使用适合数据的内部布局，但外边界对齐到 `site-container`。Projects、Skills、Chat、Settings 和简历管理页面使用相同的标题与面板规则。

Resume Workspace 使用 `site-container-wide`，保留资源库、Markdown 编辑器和树状大纲三栏。响应规则为：

- 宽桌面：三栏，中央编辑器获得主要空间。
- 中等桌面和平板横屏：缩窄两侧栏，必要时变为编辑器加一个辅助栏。
- 平板竖屏和手机：单栏排列，资源库、编辑器和大纲按工作顺序显示。

编辑器区域需要稳定的最小高度和宽度，工具栏、标题及动态状态不得造成布局跳动。

### 简历创建向导

首次创建或导入简历不再直接进入三栏 Resume Workspace，而是进入普通 `site-container` 内的分步向导。保存后的正式简历仍可进入宽工作区进行高级 Markdown 编辑、树状大纲检查、同语言合并和重新索引。

向导同时支持两种入口：

- `Import existing resume`：上传 Markdown、文本、PDF 或 Office 文件，转换并抽取内容后自动预填后续步骤。
- `Start from scratch`：从空白结构开始逐步填写。

两条路径汇合到同一套七步流程：

1. `Start`：选择创建方式和简历语言。
2. `Profile`：填写姓名、联系方式、所在地和公开链接等基本信息。
3. `Summary`：填写职业定位和职业摘要。
4. `Experience`：按时间倒序维护工作经历和职责亮点。
5. `Education`：维护教育、培训和证书信息。
6. `Skills & Projects`：维护技能、项目和其他可选内容。
7. `Review`：预览最终 Markdown、修正内容并确认保存。

导航采用半线性模式。当前步骤通过验证后才能继续；已经完成的步骤可以返回和点击；尚未到达的步骤不可跳转。桌面端在向导面板顶部显示带连接线的横向步骤器，已完成步骤显示勾选，当前步骤显示编号、标题和 `Step n of 7`。移动端改为当前步骤标题、`n / 7` 和单条进度条，避免七个标签挤压。

已评估的替代方案包括完全线性导航和所有步骤自由跳转。完全线性会让修改前面内容过于困难；自由跳转会使未验证的数据和步骤依赖变得模糊，因此不采用。

向导底部提供稳定的操作栏：左侧为 `Cancel`，右侧为 `Back` 和主要操作 `Continue`；最后一步的主要操作改为 `Save resume`。离开或刷新存在未提交内容的向导时显示确认提示。

第一版不保存向导草稿。所有步骤状态只存在于当前 Blazor 会话中；刷新、中途退出或关闭页面会丢失未提交内容。只有在 `Review` 步骤确认后才写入正式 `ResumeEntry`、拆分 sections、生成向量、刷新候选人展示数据并更新 profile hash。

如果某种语言已经存在正式简历，向导的最终保存继续遵守每用户每语言一份简历的规则：导入内容先生成 AI 合并结果并进入步骤检查，最终确认后更新现有正式简历，不创建第二条同语言记录。

`Review` 使用结构化向导状态生成只读的最终简历预览，并为每个区块提供返回对应步骤修改的入口。第一版不在向导中再嵌入完整 Markdown 编辑器；用户保存正式简历后，可以进入高级 Resume Workspace 编辑 Markdown 和检查树状大纲。这避免结构化字段与手工 Markdown 在保存前互相覆盖。

### 向导状态与数据流

前端使用单一 `ResumeWizardState` 保存当前会话状态，包括创建方式、语言、个人信息、摘要、工作经历、教育经历、技能、项目、当前步骤和已完成的最高步骤。向导外壳负责导航和验证；每一步是只读写自己字段的独立组件。

空白创建直接初始化空状态。文件导入先复用现有转换 API 得到 Markdown 和检测语言，再调用不写数据库的结构化抽取操作预填 `ResumeWizardState`。如果该语言已经存在正式简历，先复用 AI merge preview 合并正式 Markdown 与导入 Markdown，再从合并结果抽取向导字段。

结构化抽取失败时，保留当前会话中的转换 Markdown，允许用户重试或改为从空白字段继续。步骤验证失败时只在当前步骤显示字段错误。最终保存失败时保留整个内存状态和当前步骤，用户可以修正或重试。

`Review` 根据结构化状态确定性地生成 Markdown。用户确认后，前端调用现有正式简历保存流程；后端完成同语言创建或更新、section 拆分、向量生成、候选人展示数据刷新和 profile hash 更新。除最终保存外，向导 API 不写数据库。

## 视觉系统

样式令牌统一定义背景、表面、文本、边框、强调色、阴影、圆角、间距和控件高度。深色主题使用接近黑色与墨蓝的低饱和背景；浅色主题使用冷白和淡紫灰表面。两种主题都保持足够的文本和控件对比度。

玻璃效果只用于有明确边界的 Header、菜单、对话框和内容面板。页面区块本身不包装成多余的浮动卡片，也不嵌套装饰性卡片。

原有 `tool-panel`、`mac-window`、`glass-card` 和 `mica-panel` 的重复视觉规则将收敛到共享面板基础样式。业务语义类可以保留，但不再各自定义不一致的圆角、背景和阴影。

按钮、输入框、选择器和文本区域使用统一高度、字体大小和垂直对齐。主要命令、次要命令、危险命令和纯文本命令拥有清晰且一致的状态。

## 对话框和菜单

登录、注册和个人资料编辑对话框采用相同的 Obsidian Glass 窗口结构。输入框与按钮高度相协调，内容在不同模式下自然增长，不使用固定的大高度制造压迫感。

Admin 菜单与 Header 视觉连续，使用清晰的分组、悬停和焦点状态。遮罩只负责捕获外部点击，不应阻止菜单项目或页面导航。

## 交互和可访问性

- 固定 Header 不遮挡锚点、页面标题或焦点元素。
- 所有按钮和菜单项目保留可见的键盘焦点状态。
- 菜单按钮暴露展开状态，菜单拥有正确的可访问名称。
- `prefers-reduced-motion` 下缩短或关闭导航指示器、面板悬停及背景动画。
- 文本、按钮和标签在支持的视口中不得截断或相互覆盖。

## 实现边界

主要改动集中在：

- `Layout/MainLayout.razor`：新的 Header 和容器结构。
- `Layout/MainLayout.razor.css`：固定 Header、容器宽度和移动导航。
- `wwwroot/css/app.css`：设计令牌、共享面板、表单和页面节奏。
- 页面 Razor 文件：仅添加明确的普通或宽布局标记，并移除与全局外壳冲突的包装规则。
- 简历创建前端：将创建方式、步骤器、各步骤表单、会话内状态和最终预览拆分为职责明确的向导组件；高级 Markdown 工作区继续独立存在。
- 共享契约：增加结构化 `ResumeWizardDto` 及无写入的 Markdown-to-wizard 抽取请求与响应；最终保存继续使用现有正式简历保存契约。
- 相关组件测试：更新与 Header、Admin 菜单和页面容器有关的断言。

不删除现有页面或改变其 API 调用。

## 验证策略

- 构建 Blazor Client 并运行现有前端测试。
- 在未登录、Candidate、Interviewer 和 Admin 状态下检查 Header 与菜单。
- 验证 Admin 菜单在选择项目、点击外部和路由变化后关闭。
- 检查 Home、Projects、Skills、Chat、Settings、Resume Library 和 Resume Workspace。
- 使用桌面、平板和手机视口检查内容轴、Header 固定状态、文本溢出和交互区域。
- 对 Resume Workspace 检查三栏、两栏及单栏状态，并确认 Markdown 编辑器保持可用。
- 检查空白创建和文件导入两条向导路径，并确认导入内容会自动预填相同步骤。
- 检查半线性导航、步骤验证、返回修改、未保存离开提示和移动端进度显示。
- 确认 `Review` 之前不会写入正式简历、sections、vectors 或 profile hash。
- 检查结构化抽取、同语言 merge preview 后抽取、抽取重试和最终保存失败时的内存状态保留。
- 检查明暗主题下的对比度、边框、玻璃效果和焦点状态。

## 验收标准

- 普通页面的左右边界、Header 内容和页面标题在桌面端精确对齐。
- Resume Workspace 明显更宽，但仍遵循同一 Header、背景、侧边距和视觉系统。
- 创建简历使用七步向导，页面一次只呈现当前步骤所需的内容和操作。
- 导入与空白创建共享步骤模型；只有最终确认才保存并触发索引及 profile hash 更新。
- 不再显示旧的悬浮品牌块、胶囊导航或吊灯主题开关。
- 所有可见面板使用一致圆角、边框和表面处理。
- 移动端不存在 Header 控件或页面内容重叠。
- 现有认证、导航、简历编辑和公开候选人查看流程继续工作。
- 前端构建和相关自动化测试通过。
